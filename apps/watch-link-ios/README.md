# 手錶連結（iPhone 端）

搭配 [`watch/watch7-bridge`](../../watch/watch7-bridge) 使用。iPhone 上的通知、來電、媒體控制不需要這個 App；它只負責手錶自己拿不到的資料：天氣與接下來的行程。

## 狀態（0.1.0）

| 項目 | 狀態 |
| --- | --- |
| 實作 | 第一版完成 |
| 編譯與模擬器測試 | **通過**。[run 46132486827](https://github.com/chunyen627-afk/mobile-apps/actions/runs/46132486827)：9 項單元測試、2 項模擬器 UI 測試皆 0 失敗，Xcode 16.4、iPhone 16 Pro 模擬器；截圖已人工檢視。未簽署 IPA 72,023 bytes（未上傳） |
| 實機測試 | **未進行**。藍牙服務、手錶端探索、背景喚醒都還沒在 iPhone 上跑過 |

模擬器沒有藍牙，所以模擬器測試只涵蓋資料解析與畫面，測不到與手錶的連線。

## 做什麼

- 在 iPhone 上發佈一個藍牙服務。手錶連上 iPhone 後會找到它，並定時來要資料。
- 天氣：依選定的縣市向 Open-Meteo 查詢現在天氣、高低溫、降雨機率；30 分鐘內用快取。
- 行事曆：讀取未來 7 天的行程，送出最近的 5 筆。需要你在 App 內按「允許讀取行事曆」。
- iPhone 電量與目前時間。

資料只經由藍牙送到已配對的手錶，特徵要求加密連線。天氣查詢只送出所選縣市的座標，不含個人資料。

## 尚未實作

- 步數寫入「健康」。
- 應用層加密。目前只靠藍牙配對後的鏈路加密；同一支手錶上其他有藍牙權限的 App 理論上也讀得到這個服務。
- 自動定位。地點目前要手動選縣市。

## 已知限制

- App 要留在背景。從多工畫面把它滑掉，或關掉再開藍牙之後，手錶就要不到資料，直到再次打開 App。
- 被系統在背景終止後，手錶的請求能否把它叫起來，尚未驗證。
- 與手錶之間的訊息分段格式必須和手錶端 `Framing.kt` 一致，改動時兩邊要一起改。

## 建置

沿用倉庫的雲端流程：推到 `claude/watch7-bridge` 分支且改到 `apps/watch-link-ios/**` 時自動執行。步驟為產生專案、在 iPhone 模擬器跑 9 項單元測試與 2 項 UI 測試、啟動檢查、封裝未簽署 IPA。IPA 預設不上傳，只記錄大小與 SHA256。

本機（需要 Mac、Xcode 與 XcodeGen）：

```bash
bash scripts/build.sh
```

## 安裝

產物是未簽署 IPA，要用自己的 Apple 帳號簽署後安裝，做法與倉庫其他 App 相同，見 [Windows／iPhone 快速上手](../../docs/windows-iphone-quickstart.md)。免費帳號有同時 3 個側載 App 的上限；確認能用之後，預計併進工具箱。
